# Theming, grid, and section presentation

Import `@setta/workspace/styles.css` once. Package CSS is scoped to the workbench and does not
require Tailwind, a global `.dark` class, inherited application tokens, or mutation of the host
document element.

## Appearance ownership

`appearanceOptions.appearance` accepts `light`, `dark`, or `system` and defaults to `system`.
Explicit light or dark wins over the operating-system preference. System mode follows
`prefers-color-scheme` while mounted. The workbench sets its scoped `color-scheme`, semantic custom
properties, and package chrome without changing the document, viewport, selection, or host payload.

Provide partial light and dark token overrides separately:

```tsx
<Workspace
  appearanceOptions={{
    appearance: "system",
    light: {
      canvasBackground: "oklch(0.98 0.01 245)",
      selection: "oklch(0.5 0.17 250)",
    },
    dark: {
      canvasBackground: "oklch(0.16 0.025 245)",
      selection: "oklch(0.76 0.12 250)",
    },
  }}
/>
```

Overrides must be supported CSS colors. Omitted values use separately tuned light and dark
defaults; dark appearance is not generated by mechanically inverting light values. Keep theme
objects stable when practical so a host preference change does not create unrelated React work.

## Semantic theme tokens

The public `WorkspaceThemeTokens` names map to scoped CSS custom properties. Prefer the typed
appearance prop for package chrome. Host renderers may consume the documented custom properties so
their content inherits the same resolved appearance without importing package state.

| Token               | CSS custom property                    | Meaning                                    |
| ------------------- | -------------------------------------- | ------------------------------------------ |
| `canvasBackground`  | `--setta-workspace-canvas-background`  | Spatial canvas and grid backdrop.          |
| `connection`        | `--setta-workspace-connection`         | Generic edge strokes, arrows, and ports.   |
| `gridColor`         | `--setta-workspace-grid-color`         | Decorative grid marks only.                |
| `sectionBackground` | `--setta-workspace-section-background` | Default section and item surfaces.         |
| `sectionText`       | `--setta-workspace-section-text`       | Primary package and host-renderer text.    |
| `sectionMutedText`  | `--setta-workspace-section-muted-text` | Secondary labels and supporting text.      |
| `toolbarBackground` | `--setta-workspace-toolbar-background` | Toolbar, menus, and floating controls.     |
| `minimapBackground` | `--setta-workspace-minimap-background` | Minimap surface.                           |
| `selection`         | `--setta-workspace-selection`          | Selection and valid movement feedback.     |
| `focus`             | `--setta-workspace-focus`              | Visible keyboard focus.                    |
| `invalid`           | `--setta-workspace-invalid`            | Validation and rejected movement feedback. |

```css
.note-editor {
  color: var(--setta-workspace-section-text);
  background: var(--setta-workspace-section-background);
}

.note-editor__hint {
  color: var(--setta-workspace-section-muted-text);
}
```

`SectionRenderProps.appearance` also supplies the resolved `light` or `dark` value. Use it when a
renderer selects assets or non-CSS behavior; use inherited semantic variables for ordinary color.

The defaults are normalized OKLCH, stay inside sRGB gamut, and are covered by APCA and WCAG
compatibility checks. Consumer overrides remain the consumer's contrast responsibility. Preserve a
visible focus distinction and at least a 3:1 component-boundary contrast when replacing focus,
selection, or invalid colors.

## Grid appearance and snapping

`gridOptions` owns five independent values:

```tsx
<Workspace
  gridOptions={{
    visible: true,
    snap: false,
    spacing: [24, 24],
    pattern: "cross",
    markSize: 1,
  }}
/>
```

Pattern may be `dots`, `lines`, or `cross`. Spacing is expressed in workbench units and remains
aligned through pan, zoom, and negative coordinates. `markSize` changes the decorative stroke or
mark without changing snap spacing. Grid color comes from `gridColor`; it is not reused for focus,
selection, valid-drop, or invalid-drop meaning.

Visibility and snapping are deliberately separate. Snapping may remain enabled while the grid is
hidden, and a visible grid may be purely decorative. Root movement and manual root resize consume
the two-axis snap grid; ordered descendants do not.

## Chrome variants

Section presentation persists one of four variants:

| Chrome        | Intended use                           | Retained interaction contract                                                            |
| ------------- | -------------------------------------- | ---------------------------------------------------------------------------------------- |
| `default`     | Full package frame and header.         | Title, selection, movement, and selected-state actions.                                  |
| `compact`     | Denser frame chrome.                   | Same semantics and package actions in less space.                                        |
| `transparent` | Host content visually leads the frame. | Package selection, focus, title, and movement surfaces remain available.                 |
| `none`        | Headerless presentation.               | An accessible title plus selected-state selection, movement, and action surfaces remain. |

Chrome never changes containment, size mode, renderer data, or host policy. Do not use it to infer
read-only state or capability availability.

## Accents and tags

`presentation.accentColor` derives a local section surface and header treatment. `tagColor` renders
a smaller categorical marker. The default editor offers six labeled gamut-safe OKLCH values and a
reset action; `sectionColorPalette` replaces that choice set with unique labeled CSS colors.

Accent and tag values are serializable presentation, not global theme tokens. They must never be
the only cue for selection, focus, lock, minimize, read-only, invalid input, or movement validity.
The package retains independent outlines, icons, text, and semantic state for those meanings.

Avoid reusing an accent merely because it resembles success, warning, link, or error color. The
accent role is decorative or categorical. Hosts that expose a broader color picker are responsible
for validating the CSS color, checking both appearances, and preserving non-color state cues.

## Motion and host styling

Package movement, resize, marquee, and viewport feedback is immediate and restrained. Cosmetic
transitions are property-specific, interruptible, and disabled when reduced motion is requested.
Host renderers should follow the same `prefers-reduced-motion` preference and avoid entrance
animations on every reorder or canonical document update.

Do not depend on undocumented package class names or XYFlow/dnd-kit markup. Use the typed theme
tokens, inherited custom properties, `SectionRenderProps`, toolbar descriptors, registered panes,
overlay slots, and `WorkspaceInteractionBoundary` as the supported extension surfaces. Registered
pane shells inherit the scoped workbench appearance; pane renderers should use inherited semantic
colors or their own locally scoped tokens rather than mutating the host document theme.
