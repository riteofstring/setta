Footer is the click target

The compact footer is the affordance — clicking it opens the monitor. No /ps / /stop commands. When the last process exits the footer is hidden, so there is nothing to open.

Live monitor · per-process Kill

The monitor subscribes to output_delta and appends stdout/stderr live (older chunks paged). Each process has a required Kill; Kill all is allowed but secondary. Kill → terminating → exited / lost.

Lifecycle outlives the turn

The run is completed, yet both processes keep running. Start markers stay slim chronological markers — run finalization does not coerce them to the run outcome — and no late row is appended when a process exits. A later turn writing stdin adds a slim "Interacted with background terminal" marker.

Monitor host

Same component either way: an in-app overlay that shifts the chat up (shown here), or a separate Niri window. Both share the store state, endpoints, and live event stream.
