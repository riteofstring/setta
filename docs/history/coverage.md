# Feature guide and visual coverage

[Documentation](../README.md) / [History](README.md)

Start with the [illustrated history](https://setta.dev/history/) for the major changes. [Every feature](https://setta.dev/history/features/) gives each capability a dated example or explanation, and [How it worked](https://setta.dev/history/how-it-worked/) describes the engineering behind it.

This register follows meaningful feature families across versions. Each family has a stable ID, a historical period, source evidence and a public destination. The four narrative threads are **Programs**, **Workspace**, **Experiments** and **Assistants**. **Supporting** identifies useful capabilities that do not need to become a fifth thread. Several examples or periods can belong to one family.

**Motion** means a real interaction is recorded; **still** means an actual application surface is shown; **explained** means source establishes a capability that the selected media does not exercise; **experimental** identifies an exploratory implementation or interface. The limits in each row distinguish the demonstrated part from source-only details. A configured model is not a completed training run, a draft is not an executed workflow, and fixture data is not live agent work.

The [chronological feature history](feature-history.md) remains the authority for dates and product boundaries. [Technology and architecture](technology.md), [media provenance](images.md) and [focused demonstrations](feature-demos.md) supply the implementation and capture context. The site's capability catalog projects these IDs into search and thread filters; an explanation already in the chronology remains in place.

## Continuity and scope

The [continuity and removals table](feature-history.md#feature-continuity-and-removals-at-a-glance) distinguishes retained interactions from replaced systems, separate experiments and removed runtimes. In this register, local execution, sweeps/RunPlan, assistants/workflows, application generation, sharing, windows and focused applications retain their own source boundaries. The browser library does not inherit every service that once appeared beside a Setta canvas.

The archive's November 19–21 documentation work is recorded in the chronology but is not an application capability. Repository reconstruction and imported upstream history are likewise outside the feature inventory; see [methodology](methodology.md) and the [source timeline](timeline.md).
