# Always Listening openWakeWord Phase 1 Evaluator

Date: 2026-07-21

Plan: `docs/plans/always-listening-openwakeword-20260721.md`

## Outcome

This repository now has a dependency-free offline evaluator for wake-score
traces:

```sh
python3 scripts/evaluate_openwakeword_offline.py \
  --manifest path/to/manifest.json \
  --threshold 0.60
```

The evaluator accepts labeled WAV fixtures and JSONL score traces generated by
an openWakeWord runtime. It validates the Phase 1 engine input format, `16 kHz`
mono PCM16, then reports per-fixture maximum scores, first threshold crossings,
positive false rejects, negative false accepts per hour, and accepted wake
latency.

## Manifest Contract

```json
{
  "fixtures": [
    {
      "id": "speaker_near_normal_rate",
      "label": "positive",
      "wav": "audio/speaker_near_normal_rate.wav",
      "scores": "scores/speaker_near_normal_rate.jsonl",
      "wakeStartMs": 320,
      "wakeEndMs": 900
    },
    {
      "id": "office_conversation_001",
      "label": "negative",
      "wav": "audio/office_conversation_001.wav",
      "scores": "scores/office_conversation_001.jsonl"
    }
  ]
}
```

Each score trace is newline-delimited JSON with explicit runtime output:

```json
{"timeMs": 480, "score": 0.72}
```

The evaluator does not infer scores from audio. That boundary is intentional:
the actual model/runtime spike must produce score traces from packaged app
resources before threshold or accuracy claims can be made.

## Repository-Local Verification

Focused tests generate temporary WAV fixtures and score traces:

```sh
python3 scripts/evaluate_openwakeword_offline_test.py
```

Coverage includes accepted wake timing, false rejects, false accepts per hour,
CLI JSON output, WAV format rejection, and score rows that exceed fixture
duration.

## External Release Gate

The following Phase 1 evidence is not available in this implementation loop and
is not counted as complete repository work:

- the first Setta-owned `Hey Setta` model artifact, hash, and provenance;
- generated score traces from openWakeWord running out of packaged app
  resources without user Python;
- measured ONNX Runtime versus TFLite packaging/runtime behavior;
- a candidate threshold selected from real positive and negative fixtures; and
- false-accept, false-reject, latency, CPU, memory, and battery measurements.

Those items remain release gates for the engine spike. They require the model
artifact, runtime integration, fixture corpus, or dogfood measurements rather
than additional status-only repository commits.
