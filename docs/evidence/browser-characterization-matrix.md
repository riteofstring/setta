# Browser Characterization Matrix

## Scope

This matrix separates three kinds of evidence: historical application scenarios retained as
behavioral references, executable Phase 0 package/playground proof, and the later phase that must
prove the complete standalone feature. A missing historical browser test is recorded as such; it
does not authorize restoring the application or treating an unobserved implementation detail as a
contract.

Historical paths refer to source snapshot
`043d3b2e9c69caf99d1246f1408b3ad7194b7864`. The complete machine-checked path list lives in
`packages/workspace/tests/fixtures/interaction-evidence.ts`.

## Phase 0 harness coverage

| Gate behavior                        | Executable browser evidence                                                                                                                              |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keyboard completion and cancellation | Trusted dnd-kit keyboard workflows in `adapter-proof.spec.ts` emit one accepted command or none when canceled.                                           |
| Focus restoration                    | The same workflows assert the structural handle retains/restores focus after accepted completion and cancellation.                                       |
| Accessible names, roles, and states  | Native playground/adapter controls are queried by role and name; pressed, grabbed, live-status, and disabled states are asserted.                        |
| Dynamic announcement                 | Playground creation and adapter interaction status regions are asserted after changes.                                                                   |
| Automated accessibility              | Axe scans the populated blank playground and representative adapter proof with no violations.                                                            |
| 200% zoom                            | `playground.spec.ts` uses Chromium's page-scale emulation, verifies a scale of 2, and completes the primary add-section workflow.                        |
| Reflow and reduced motion            | Both playground and adapter surfaces run at 320 CSS pixels with reduced motion and no horizontal overflow; reviewed screenshot baselines are checked in. |
| Representative visual state          | Playwright compares the blank 320-pixel and adapter-proof 1280-pixel screenshots.                                                                        |

Repository Playwright is the available automated browser and visual evidence. Interactive in-app
CDP review remains a separately recorded external release gate because no connected browser surface
was available on 2026-08-08; routine implementation must not repeatedly probe it.
