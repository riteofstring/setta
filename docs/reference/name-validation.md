# Name Validation

This document describes how Setta validates names for projects, view modes,
sections, and params, and where those rules are enforced in the backend and
frontend.

## Where Validation Lives

- Backend (authoritative): `backend/setta/utils/name_validation.py`
- Backend error types: `backend/setta/utils/errors.py`
- Frontend input validation: `frontend/src/utils/nameValidation.ts`
- Frontend view mode editor: `frontend/src/components/Panes/Overview/ViewingEditingMode.tsx`
- Frontend window-space editor: `frontend/src/components/Panes/Overview/WindowSpacesPane.tsx`
- Frontend section checks: `frontend/src/components/Section/Header/SectionTitle.tsx`
- Frontend param checks: `frontend/src/components/Params/ParamItems/ParamNameInput.tsx`
- Name error broadcast: `backend/setta/project_state/base_project_manager.py`
  `_broadcast_name_validation_errors`

## Normalization

All names are normalized with `str.strip()` before validation. The trimmed value
is what gets stored.

## Common Format Rules (Project + View Mode + Section)

Applied by `validate_project_name_format` and `validate_section_name_format`:

- Name must be non-empty.
- Control characters are disallowed (ASCII < 32 or DEL).
- Path separators are disallowed (`/` and `\\`).
- `..` path segments are disallowed.
- Only letters, numbers, spaces, `_`, and `-` are allowed.
- Reserved names:
  - Project: `home` and the Settings project name (`C.SETTINGS_PROJECT_NAME`).
  - View mode: `home` and the Settings project name (`C.SETTINGS_PROJECT_NAME`).
  - Section: currently none (empty reserved list).

## Project Names

### Format and Uniqueness

- Format rules come from `validate_project_name_format`.
- After format validation, `validate_project_name` checks for slug collisions
  against all existing project configs.
- Slugs are generated by `sanitize_slug` in `backend/setta/code_gen/utils.py`:
  - Replaces `[]"'` and spaces with `_`.
  - Collapses repeated underscores.
  - Trims leading/trailing underscores.
  - Case-folds to lower case.
- The slug must be non-empty; otherwise the name is rejected.
- Two different names that sanitize to the same slug are considered conflicts.

### Errors and API Responses

- `InvalidProjectName` is raised for violations.
- Project rename/create routes translate this to HTTP 422 in
  `backend/setta/routers/projects.py`.

## View Mode Names

### Format and Uniqueness

- Format rules come from `validate_view_mode_name_format`.
- After format validation, `validate_view_mode_name` checks for slug collisions
  against existing view modes in the same project config.
- Slugs are generated by `sanitize_slug` in `backend/setta/code_gen/utils.py`
  (same rules as project names).
- The slug must be non-empty; otherwise the name is rejected.
- Two different view mode names that sanitize to the same slug are considered
  conflicts.

### Errors and API Responses

- `InvalidViewModeName` is raised for violations.
- View mode rename routes translate this to HTTP 422 in
  `backend/setta/routers/project_manager.py`.

## Window Space Names

### Format and Uniqueness

- Format rules come from `validate_window_space_name_format`.
- After format validation, `validate_window_space_name` checks for slug
  collisions against existing window spaces in the same project config.
- Slugs are generated by `sanitize_slug` in `backend/setta/code_gen/utils.py`
  (same rules as project and view mode names).
- The slug must be non-empty; otherwise the name is rejected.
- Two different window-space names that sanitize to the same slug are
  considered conflicts.
- Window-space names do not reserve `home`, `settings`, `chat`, or
  `windowspace`; the explicit `/windowspace/<slug>` route namespace removes the
  need for reserved route words here.

### Errors and API Responses

- `InvalidWindowSpaceName` is raised for violations.
- Window-space rename/create routes translate this to HTTP 422 in
  `backend/setta/routers/project_manager.py`.

## Section Names

### Format and Conflict Checks

`validate_section_name` enforces format rules plus:

1. **Sibling duplicates**: a section name cannot exactly match another sibling
   under the same parent (after trimming).
2. **Top-level Python identifier conflicts**: top-level section names are
   sanitized with `sanitize_python_identifier`, and the sanitized identifiers
   must be unique among top-level sections.
3. **Full-path slug conflicts**: every section’s full path name is built using a
   bracketed path representation and then sanitized with `sanitize_slug`. The
   resulting slug must be unique across all sections and must be non-empty.

### Full Path Name Shape

The slug is based on a full path string built by walking ancestors:

- List-root parents append `[index]` (the child’s position in that list).
- Other parents append `["Child Name"]`.
- Example: `Root["Child"][0]["Leaf"]`.

This ensures file and codegen paths are stable and collision-free across the
section tree.

### Text Block Heading Names

When a TextBlock section has `headingAsSectionName = true`, its first markdown
heading is treated as a candidate name. The backend validates that heading
against the same rules and reports errors as:

- `Text block heading cannot be used as section name: ...`

### Errors and API Responses

- `InvalidSectionName` is raised for violations.
- Section rename routes translate this to HTTP 422 in
  `backend/setta/routers/project_manager.py`.

## Param Names

### Format Rules

`validate_param_name_format` applies rules that depend on the section type and
codegen settings:

- Names are trimmed before validation.
- Empty names are allowed only when:
  - `BaseParamCodeObjImpl.coreNameEditable` is true, or
  - The param is the dict section’s `topLevelParamId`.
- Control characters are always disallowed.
- For non-dict sections:
  - Path separators (`/`, `\\`) are disallowed.
  - `..` path segments are disallowed.
  - Reserved names are checked (currently empty).
  - If Python codegen is enabled for the project, the name must be a valid
    Python identifier and must not be a keyword or soft keyword.
- Dict sections skip the path checks and Python identifier requirements.

### Conflict Checks

`validate_param_name` rejects duplicate sibling names under the same parent in
that param hierarchy. The check is exact-match after trimming.

### Errors and API Responses

- `InvalidParamName` is raised for violations.
- Param rename routes translate this to HTTP 422 in
  `backend/setta/routers/project_manager.py`.

## Validation Flows

### Immediate Validation (Rename Operations)

- Project rename: `set_project_config_name` -> `validate_project_name`.
- View mode rename: `set_view_mode_name` -> `validate_view_mode_name`.
- Section rename: `set_section_name` -> `validate_section_name`.
- Param rename: `set_code_obj_name` / `set_param_name_and_value` ->
  `validate_param_name` (or `validate_param_name_format` for meta controls).

### Project State Updates

- `ProjectStateSingleConfig.validate_name_rules` runs **format-only** validation
  (no conflict checks) as part of `validate_for_update`.
- `_broadcast_name_validation_errors` runs conflict checks and aggregates format
  errors for the project, sections, params, and text-block headings, then sends a
  `SettaProjectNameValidationErrors` websocket message.
- View mode names are not currently included in the broadcast payload; they are
  validated only on rename.

### Frontend Behavior

- Local validation runs in the UI for instant feedback using
  `utils/nameValidation.ts` plus section/param-specific checks.
- Backend-sent name validation errors take precedence in UI displays.
