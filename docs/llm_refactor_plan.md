**Observations**  
- Backend chat orchestration is entirely Anthropics-bound: `backend/setta/mcp/chat_manager.py` instantiates `AsyncAnthropic`, streams raw Anthropics events, persists `anthropic.types.ContentBlock`s (`backend/setta/types/chat_messages.py`), and even the regression tests (`tests/project_state/chats`) assert on Anthropics classes. Nothing here is reusable for Portkey or any non-Anthropic vendor.  
- The MCP client/server/tooling stack is a brittle proof-of-concept: `backend/setta/mcp/client.py` is a custom SSE loop that bypasses MCP when the tool name is `str_replace_editor`, and `backend/setta/mcp/str_replace_editor_tool_fns.py` literally performs global string substitution on disk. Only two “real” tools (`backend/setta/mcp/tools.py`) exist, so the LLM can’t call meaningful project operations.  
- Frontend chat/state is hard-coded to Anthropics events and fake tools: `frontend/src/state/actions/ai.ts` (≈600 LOC) consumes `message_start/content_block_delta` enums from `C.LLM_*`, stores the raw Anthropic payloads, and exposes `startStreamingInto`/`deleteTextRange` functions that never reach the backend—they mutate Zustand state directly. `ProjectChatCore.tsx` renders these provider-specific objects, so the entire UI would have to be rewritten for a new wire format.  
- Secrets + model selection are static: the backend writes `.env` files directly (`backend/setta/routers/ai.py:85-128`), while the frontend renders a fixed `MODEL_GROUPS` array (`frontend/src/utils/constants.ts:138-158`). There’s no validation, masking, or Portkey route awareness.  
- Server init locks in the MCP transport: `backend/setta/server_state.py` creates the SSE MCP server/client globally and injects it into `ChatManager`, making it impossible to swap in Portkey or new transports without rewriting startup code.

**Progress**  
- Deleted the Anthropics-only backend stack: removed `backend/setta/mcp/`, `backend/setta/types/chat_messages.py`, `backend/setta/project_state/chats/`, and `tests/project_state/chats/` to unblock the new provider-agnostic LLM architecture.

**Ruthless Assessment**  
- Delete the entire `backend/setta/mcp/` package (≈1.1K LOC) plus `backend/setta/types/chat_messages.py`, `backend/setta/project_state/chats/`, and `tests/project_state/chats/`. Each file encodes Anthropics-specific types and SSE assumptions; rewriting pieces would cost more than starting over with provider-agnostic models.  
- Nuke the frontend AI stack: `frontend/src/state/actions/ai.ts`, `frontend/src/components/Panes/Overview/ProjectLevelAI/ProjectChatCore.tsx`, `frontend/src/components/Panes/Overview/ProjectLevelAI/ProjectLLMSettings.tsx`, and the Anthropics constants in `frontend/src/utils/constants.ts` should all be replaced. Nothing there survives a provider swap, and we’re not obligated to keep backward compatibility.  
- Drop DB chat storage that speaks Anthropics (`backend/setta/database/db_objs.py:143-165` plus `setta_files/chats`). Either delete old transcripts or build a one-time migration script; don’t carry the old schema forward.  
- Replace the `.env` mutation path with a secrets/route service. The current approach can’t handle multiple providers, Portkey routes, or validation, so reimplementing it is cheaper than trying to extend it.  
- Revisit `SettaFastAPIState`: rip out MCP wiring and make the chat/LLM services lazily constructed, provider-agnostic components. Treat the current startup block as throwaway bootstrap code.

**Plan**  
- Stand up a new `backend/setta/llm/` package that defines internal conversation/tool models, Portkey client wrappers, streaming parsers, and persistence interfaces. Remove Anthropics from dependencies and delete the old MCP/chat modules before wiring the new service into `backend/setta/routers/ai.py` and `WMHFrontendSender`.  
- Build a real tool runtime—exposing project, filesystem, generator, and terminal operations—using the existing `setta_tool` decorator. Tools must send structured progress/results that Portkey can surface as tool-call deltas, replacing the `str_replace_editor` shortcut entirely.  
- Rewrite the frontend chat experience on top of provider-agnostic data: a new AI store, websocket handlers, and `ProjectChatCore` that understand normalized `LLMMessage` / `LLMStreamChunk` shapes (text deltas, tool call lifecycle, tool results, stream completion) and can render tool UIs + live section edits emitted by the backend tools.  
- Replace the API key + model UX with a Portkey-aware settings flow: backend endpoints for listing routes, validating keys, and persisting scoped secrets; frontend forms for adding/removing/testing providers, masking values, and reacting to watcher updates.  
- Refactor server startup so chat services, MCP/Portkey transports, and websocket broadcasters are created through explicit factories rather than global singletons. This allows new transports (Portkey, direct HTTPS) without touching unrelated modules.  
- Add tests/docs for the new architecture: Portkey streaming parsers, conversation persistence, tool runtime, and the new settings endpoints. Document manual verification steps (e.g., Portkey route creation, `pnpm start`, `python -m unittest discover tests`) so contributors can reproduce the flow end-to-end.
