In this approach, all code information is just strings.
Parameters/kwargs of objects are stored as "collections".
The downside of this is that kwarg names have to be updated in 3 places:
- Collection
- EV Collection
- UIType Collection


Section:
	id: uuid
	SelectedItem: torchvision.models.resnet101


Collection:
	id: uuid
	parent: torchvision.models.resnet101
	child: pretrained
	editable: false

	id: uuid
	parent: torchvision.models.resnet101
	child: download
	editable: false

	id: uuid
	parent: torchvision.models.resnet101
	child: my_special_kwarg
	editable: true


EV Collection
	evColId: uuid
	objName: torchvision.models.resnet101
	paramName: pretrained
	value: value

	evColId: uuid
	objName: torchvision.models.resnet101
	paramName: my_special_kwarg
	value: value

In this approach, every object and param has an id.
This is the existing approach.
The downside can be illustrated with this example:
- section X has resnet101 and its parameters. Each have unique ids
- user enters resnet101 into section Y. These end up having new ids. However this is not really any worse than the above approach.
- if we want an EV Collection or UIType Collection to be usable in multiple sections 


Section:
	id: uuid
	SelectedItem: uuid
	Collections: [uuid, uuid, ...]


CodeInfo:
	id: uuid
	name: torchvision.models.resnet101
	editable: false

	id: uuid
	name: pretrained
	editable: false

	id: uuid
	name: download
	editable: false

	id: uuid
	name: my_special_kwarg
	editable: true


Collection:
	id: uuid
	parent: uuid
	child: uuid
	order: 0

	id: uuid
	parent: uuid
	child: uuid
	order: 1

	id: uuid
	parent: uuid
	child: uuid
	order: 2


This is the approach to allow an the exact same ev collection to be used in multiple places:

EV Collection
	evColId: uuid
	codeInfoId: uuid
	evId: uuid

	evColId: uuid
	codeInfoId: uuid
	evId: uuid

EV
	evId: uuid
	value: value


If we don't need to allow that (i.e. just make copies of ev collections), then do:

EV Collection
	evColId: uuid
	codeInfoId: uuid
	value: value

	evColId: uuid
	codeInfoId: uuid
	value: value


This approach might also work if when making a reference to an ev collection, we have a codeinfo mapping which maps from the new section's codeinfo ids to the old section's codeinfo ids.
